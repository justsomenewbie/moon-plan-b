# Display method and scientific limits

The live terrain summary uses the team’s producer model and the supplied Sun, Earth and simultaneous intervals. It reports requested and evaluated UTC ranges, coverage against each, and the run and source evidence. The checked SPICE/PGDA run samples hourly. Its visibility intervals can miss sub-hour events, and its transitions are uncertain by one hour. See the [source checks](BACKEND_RECONCILIATION.md#aggregate-update-on-14-november).

The default mock workspace uses invented demonstration data. The fixture has fictitious sites with no coordinates; its simple angles and precomputed intervals exist to exercise interactions and missing-data behavior.

JPL Horizons supplied the separate ideal-horizon browser fixtures. The [Horizons observer-table documentation](https://ssd.jpl.nasa.gov/horizons/manual.html#observer-table) describes azimuth/elevation quantities. A future producer must confirm the actual target, observer, body-fixed location/frame, airless apparent-angle definition, UTC conversion and source coverage before integration. The frontend's draft conventions are recorded in [the contract](FRONTEND_CONTRACT.md), not assumed to match an unseen response.

For the proposed ideal-horizon center model, elevation greater than 0° denotes a center above the local ideal horizon. Exactly 0° is the boundary. The producer supplies all intervals, total durations, longest simultaneous duration and criterion assessments. Structural agreement between these fields is checked at import; it is not independent scientific validation. The frontend only selects, compares, plots and presents supplied values.

For a compatible JSON release, run `node frontend/scripts/check-joint-intervals.ts path/to/release.json` from the repository root with the project’s Node 24 runtime. This offline check validates the release structure, intersects the supplied Sun and Earth UTC intervals for each complete scenario, and compares every covered span with the supplied simultaneous set. The output includes both UTC lists, totals and longest durations. Touching segments within either list are combined for time coverage. If that changes the reported longest duration by at least 0.001 hours, the tool flags it for review. Inspect the producer’s boundary evidence before treating adjacent entries as a single physical event. Partial or missing scenarios stay unassessed. The command exits unsuccessfully for invalid input, an interval mismatch, a longest-duration review or a release with no complete scenarios. Independent source and window checks are still required for scientific validation.

The chart joins observed samples with straight segments for display. It does not create new samples or use that drawing to calculate results. Gaps and null values break the line. The cursor selects actual common sample offsets. The 3D local sky projects supplied azimuth (clockwise from north) and elevation into a local east/north/up coordinate frame. The compass ring marks zero elevation. Changing the orbit rotates the display and preserves the observation. Switching between windows uses each scenario’s own UTC at the shared elapsed time. Missing bodies have no marker. This direction diagram uses an ideal horizon and has no site topography.

The 2D sky chart plots azimuth horizontally and elevation vertically; it is a schematic, not terrain or a perspective camera view. Sample tables preserve supplied numeric values; summary durations and angle readouts are explicitly rounded for readability.

Terrain obstruction, crater/mountain shadows, disk edges, eclipses, electrical generation/storage/load, antenna configuration, ground stations and radio link budgets are not modeled by this frontend draft. Earth above an ideal horizon does not establish communication. Sun above it does not establish usable power. No displayed result establishes landing safety or a best landing site. Cadence can hide short events; interpolation or agreement between two numeric summaries cannot establish physical accuracy.

The interactive surface globe uses an orthographic sphere and a north-up NASA color map centered on the lunar prime meridian. Rotation changes the viewing center. Its fixed display shading carries no observation time, terrain elevation or landing-site prediction. Ground-level rendering would require compatible sourced terrain, site coordinates and elevation data. The responsive chart/table experience remains usable without WebGL. Scientific review and final device acceptance remain outstanding.

## Site locations on the reference globe

The locator shows the reported landing regions of Odysseus (80.13° S, 1.44° E) and Athena (84.7906° S, 29.1957° E). Selecting a mission reference moves the camera and leaves the dataset, UTC window and assessments intact. These locations are reference examples. [NASA Odysseus position](https://www.nasa.gov/missions/lro/nasas-lro-images-intuitive-machines-odysseus-lander/) · [LROC Athena position](https://lroc.im-ldi.com/featured_sites/im2/flip-book)

The NASA texture is centered at zero longitude and adapted from the LROC WAC mosaic. The LROC RDR specification, section 4, describes planetocentric latitude and east-positive longitude in the lunar mean Earth/polar-axis system. The SVS derivative has no stated site-level registration accuracy. Markers show approximate regions on the smooth sphere. A point on the limb or hidden hemisphere has no visible ring. [NASA CGI Moon Kit](https://svs.gsfc.nasa.gov/4720/) · [LROC RDR coordinate specification](https://pds-imaging.jpl.nasa.gov/documentation/LROC_SOC_RDR_SIS_Spec_4_v1-2.pdf)

For an imported release, the current draft locator accepts a sourced site with computed-ephemeris evidence whose frame explicitly declares both `MOON_ME_DE421` and `planetocentric` (for example, `MOON_ME_DE421 (planetocentric)`). The draft already requires degrees and east-positive longitude. Other frame descriptions stay available verbatim in Sources & method. The same observation can still open in the 3D sky when coordinates are missing, synthetic or incompatible. Elevation and terrain do not enter the marker projection.
